UgCore is a FiveM framework for roleplay and gameplay servers. Its core resource, `ug-core`, gives you players, characters, money, jobs, permissions and more, behind an API that treats every client as hostile until proven otherwise.

## Why UgCore

FiveM clients can be modified. Anything a client sends can be forged: a price, an amount, a position, an outcome. UgCore is built around one rule:

<Note>
  **Clients send intent, never results.** The server computes prices, amounts, rewards and outcomes, and reads positions from the ped on the server.
</Note>

On top of that rule, UgCore adds:

<Columns cols={2}>
  <Card title="Layered protection" icon="layer-group" href="/concepts/security">
    Schemas, rate limits, server authority and Guard scoring. Each layer works even when the others fail.
  </Card>
  <Card title="A headless core" icon="ghost" href="/architecture">
    No NUI, no notifications, no drawing. The core returns result codes and emits events for UI resources.
  </Card>
  <Card title="Modules you choose" icon="puzzle-piece" href="/owners/modules">
    Turn off accounts, gangs or sessions in one file. Disabled modules leave nothing behind.
  </Card>
  <Card title="A typed API" icon="code" href="/api/overview">
    Every function is annotated for the Lua language server, so editors catch typos and wrong types as you write.
  </Card>
</Columns>

## The ecosystem

UgCore is split into resources with strict boundaries:

| Resource | Role |
| --- | --- |
| `ug-core` | The framework: state, validation, networking, modules. Headless. |
| `ug-lib` | UI components and pure utilities. No network, no state. |
| Feature resources | `ug-multicharacter`, `ug-spawn`, `ug-hud` and others. They use both. |

`ug-core` and `ug-lib` never depend on each other. `ug-core` depends only on OneSync and `oxmysql`.
